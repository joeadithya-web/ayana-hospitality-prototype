# AYANA MASTER BUILD PROMPT

## PART 2 OF 4 --- Traveller Application

> Continue from Part 1. Build the Traveller App first before moving to
> the Dashboard or Kiosk.

# OBJECTIVE

Build a premium mobile-style responsive web application that
demonstrates the complete **HTR (Home-To-Room)** journey.

The application must feel production-ready and synchronize in real time
with the Hotel Dashboard, Kiosk and Simulation Engine.

------------------------------------------------------------------------

# PRIMARY NAVIGATION

-   Splash
-   Login / Register
-   Dashboard
-   Search Hotels
-   Hotel Details
-   Room Selection
-   Booking
-   Payment
-   Ready-To-Room
-   My Trips
-   In-Stay
-   Concierge
-   Checkout
-   Profile
-   AYANA Memory
-   Notifications
-   Support

------------------------------------------------------------------------

# AUTHENTICATION

Simulate:

-   Email login
-   Mobile login
-   OTP verification
-   Aadhaar verification
-   Face verification

Never call external APIs.

Display believable progress and success/failure messages.

------------------------------------------------------------------------

# DASHBOARD

Display:

-   Upcoming Stay
-   Previous Stays
-   AI Recommendations
-   Favourite Hotels
-   Loyalty Status
-   Quick Actions
-   Notifications

------------------------------------------------------------------------

# HOTEL SEARCH

Filters:

-   City
-   Dates
-   Guests
-   Price
-   Star Rating
-   Business / Leisure
-   Airport Hotel
-   Amenities

Use at least 15 mock hotels.

------------------------------------------------------------------------

# HOTEL DETAILS

Show:

-   Images
-   Description
-   Amenities
-   Room Categories
-   Reviews (mock)
-   Map (mock)
-   Available Offers

------------------------------------------------------------------------

# ROOM SELECTION

The AI Engine must recommend a room based on AYANA Memory.

Show:

-   AI Recommended Room
-   Alternative Rooms
-   Floor
-   Section
-   View
-   Occupancy
-   Upgrade Price

Include a clickable floor layout.

------------------------------------------------------------------------

# AYANA MEMORY

Provide a dedicated screen where users manage:

-   Vegetarian / Non-Vegetarian / Vegan / Jain
-   Smoking / Non-Smoking
-   Preferred View
-   Preferred Floor
-   Temperature
-   Pillow Type
-   Accessibility
-   Airport Pickup
-   Favourite Payment Method
-   Special Requests

Changes must affect AI recommendations immediately.

------------------------------------------------------------------------

# BOOKING

Workflow:

Search → Select Hotel → AI Room Recommendation → Select Room → Confirm
Stay → Payment

Support:

-   100% Payment = Guaranteed
-   50% Payment = Hold until 6 PM
-   25% Payment = Hold until 6 PM, no refund after release
-   0% Payment = Booking rejected

------------------------------------------------------------------------

# PAYMENT

Simulate:

-   UPI
-   Credit Card
-   Wallet
-   Gift Card
-   Cash (Front Desk)

Generate transaction IDs.

Support success and failure scenarios.

------------------------------------------------------------------------

# READY-TO-ROOM

Display:

-   Booking Confirmed
-   Identity Verified
-   Payment Verified
-   Room Ready
-   Pickup Status
-   QR Code
-   Estimated Arrival

Animate each milestone.

------------------------------------------------------------------------

# IN-STAY EXPERIENCE

Allow guest to:

-   View Room Charges
-   View F&B Charges
-   Pay Outstanding Balance
-   Request Housekeeping
-   Request Concierge
-   Book Transport
-   Order Add-ons
-   Chat (simulated)

Balance must update in real time.

------------------------------------------------------------------------

# CHECKOUT

Workflow:

View Outstanding → Pay Balance → Zero Balance → Digital Invoice →
Feedback → Voucher → Rebook

Generate invoice and voucher using mock data.

------------------------------------------------------------------------

# SYNCHRONIZATION

Every action must instantly update:

-   Hotel Dashboard
-   Kiosk
-   Simulation Engine

Example:

Guest pays balance → Dashboard reflects payment → Checkout enabled →
Kiosk exit validation succeeds

------------------------------------------------------------------------

# ACCEPTANCE CRITERIA

-   Every screen is functional.
-   No placeholder content.
-   Modern luxury UI.
-   Fully synchronized with Simulation Engine.
-   All data comes from shared mock state.
